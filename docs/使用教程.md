# SocksTun 使用教程

面向使用者：从安装到日常使用，以及常见问题排查。实现细节见
[启动与架构说明.md](./启动与架构说明.md)。

引擎是内嵌的 **mihomo（Clash.Meta）**，所以订阅里的 vmess / vless / trojan / shadowsocks / hysteria2 / tuic / socks5 等节点**都能用**，不限于 SOCKS5。

---

## 1. 三分钟上手

有两种用法，选一种即可。

### A. 用订阅（推荐，多协议）
1. 底部 **订阅** → 粘贴 `clash.yml` 订阅地址 → 点「拉取订阅」。
2. 点「测速全部」，等列表出现延迟。
3. 在想用的节点上点「使用」。
4. 回底部 **首页** → 点「连接」→ 系统 VPN 授权框点确定。

### B. 只用手动 SOCKS5（不用订阅）
1. 底部 **服务器** → 「新增服务器」→ 填名称 / 地址 / 端口 /（用户名密码）→ 保存。
2. 在列表里点该服务器的「**启用**」，它就会作为上游（**自动忽略订阅**）。
3. 回首页点「连接」。

> Android 13+ 首次会要**通知权限**，请允许，否则看不到常驻通知。

---

## 2. 权限

| 权限 | 用途 | 何时 |
| --- | --- | --- |
| VPN（系统弹窗） | 建立 TUN 接口 | 第一次点连接 |
| 通知 `POST_NOTIFICATIONS` | 常驻通知与流量 | Android 13+ 首次启动 |
| 开机自启 | 上次是连接状态时，重启后自动恢复 | 无弹窗 |

无通讯录/短信/定位等敏感权限。

---

## 3. 首页与底部导航

底部 5 个标签：**首页 · 订阅 · 服务器 · 规则 · 设置**。

首页内容：

- **状态卡片**：已连接 / 未连接，下方显示**当前生效的节点**与**出口 IP**。
- **连接 / 断开** 按钮。
- **配置档名**：左右箭头切换，长按可重命名 / 新增 / 删除。
- **流量卡片**：实时 / 本次 / 累计 + Top 应用，带「重置累计」。

> **出口 IP**：连接后每隔 60 秒通过内核的本地 HTTP 端口（7890）查询一次，所以显示的是**代理暴露出去的地址**，不是手机本身的地址，可用来确认代理是否真的生效。显示「IP：未获取」通常是代理端口没起来或当前节点不可用。

> 连接状态下不能切换配置档（按钮置灰），先断开。

通知栏：标题是当前节点，正文是实时速率，展开后能看到节点、实时、本次、累计，以及「断开」按钮。

## 4. 订阅

- **拉取**：填地址（普通 YAML 或 base64 均可）→ 「拉取订阅」。支持订阅里的**全部协议**节点。
- **测速**：单个「测速」或「测速全部」，对节点做 TCP 连接计时（3 秒超时）。
  - 绿色 `123 ms` = 可用；红色「不可用」= 连不上；灰色「未测速」。
  - 结果会保存，下次打开还在。
  - 这只是**握手延迟**，不代表实际带宽。
- **排序 / 筛选**：页面顶部两个下拉框，可按延迟排序（快→慢，失败的沉底），并筛选「全部 / 仅可用 / 仅不可用」。页面下方显示「可用 x · 不可用 y · 共 z」。
- **使用**：
  - 隧道**未连接**时点「使用」：记住节点，下次启动隧道时生效。
  - 隧道**已连接**时点「使用」：**立即切换**，不用重连。
  - 选中节点会高亮并显示「使用中」。
- **使用说明**：订阅页有「使用说明」按钮，内有完整流程。

### 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 提示「未能从订阅解析到任何节点」 | 订阅不是含 `proxies:` 列表的标准 clash.yml；或当时解析失败。确认用浏览器打开地址能看到 `proxies:` |
| 能列出节点，但点「使用」提示没有可切换策略组 | 订阅里没有 `proxy-groups`（select/url-test 等），此时内核按订阅自带默认节点走 |
| 节点全是「不可用」 | 手机到该节点的网络不通（并非 App 问题），换个节点或换个网络试试 |

## 5. 服务器（SOCKS5 服务器列表）

这里管理多套 SOCKS5 上游，每台可独立新增 / 修改 / 删除：

| 项 | 说明 |
| --- | --- |
| 名称 | 选填，方便区分；留空则显示 `地址:端口` |
| 服务器地址 / 端口 | SOCKS5 服务端 IP 或域名，端口默认 1080 |
| 用户名 / 密码 | 选填 |

- **启用**：点列表里的「启用」，该台即成为上游，并**自动忽略订阅**（列表会显示「启用中」）。
- **取消启用**：到订阅页选一个节点即可自动取消；或删除这台服务器。
- 同一时刻只有一台生效；删除正在启用的那台会回到订阅。

> 换服务器 / 改参数后需要**重启一次隧道**才生效。

---

## 6. 规则（分流 → DNS → 路由规则）

底部「规则」页把原来分散的三项按顺序合到一页：

**1) 分流**
- **全局模式**：所有应用走隧道（自身除外）。
- **按应用模式**：点「应用」勾选要走隧道的应用，未勾选的不走（自动排除本 App）。
- IPv4 / IPv6、UDP over TCP 也在这里。

**2) DNS**
- DNS IPv4 / IPv6、远程 DNS。

**3) 路由规则**
- 「未命中的流量走代理」开关，以及规则列表（域名 / IP / IP 段 → 代理或直连）。

> 在 mihomo 引擎下：**分流生效**；**DNS 与路由规则暂未接入内核** —— DNS 与分流规则由订阅自带的 `dns:` / `rules` / `rule-providers` 在内核里处理。要自定义规则，请直接改订阅内容，App 会原样交给内核。

## 7. 设置

「设置」页里四项，点进去看具体内容：

| 项 | 点进去是什么 |
| --- | --- |
| 应用 | 按应用模式勾选要走隧道的应用 |
| 日志 | 开关「记录日志」+ 查看日志，**下次连接生效** |
| 主题 | 5 套配色的选择框（霓虹绿 / 赛博青 / 暗夜紫 / 琥珀橙 / 极简白） |
| 版本 | 版本信息弹窗：版本号、版本码、mihomo 内核版本、支持的 ABI |

---

## 8. 配置档

一整套独立配置（订阅、上游、分应用、DNS、规则等），最多 **13** 套。

- 切换：首页 `◀ / ▶`
- 新增：长按配置名 → 新增（复制当前档）
- 重命名 / 删除：同上；最后一个不能删

## 9. 流量统计

```
实时  ↑ 128.4 KB/s  ↓ 1.20 MB/s
本次  ↑ 12.3 MB     ↓ 96.7 MB
累计  ↑ 1.20 GB     ↓ 8.44 GB
```

- 每 1.5 秒刷新。
- 三项总量来自 mihomo 计数器，准确。
- 每应用来自系统 `TrafficStats`，**包含未走隧道的流量**，仅供参考。

## 10. 常见故障速查

| 现象 | 优先检查 |
| --- | --- |
| 点连接提示内核加载失败 | 日志里 `FATAL: failed to load mihomo core`，多为 ABI/包问题，重装 |
| 拉取失败 | 订阅地址能否在浏览器打开；是否 HTTP 非 200 |
| 解析不到节点 | 见 §4；订阅是否含 `proxies:` |
| 连上但打不开网页 | 换个节点；确认节点可用（测速绿色） |
| 换了节点但没变化 | 是否点了「使用」；隧道是否已连接（未连接则下次启动生效） |
| 通知不显示 | Android 13+ 通知权限；渠道是否被系统静音 |
| 看不到日志 | 日志开关下次连接才生效 |

---

## 11. 已知限制

| 限制 | 说明 |
| --- | --- |
| 节点测速只是 TCP 握手延迟 | 不代表实际带宽/速度 |
| 每应用流量包含隧道外流量 | Android 只提供按 UID 的设备级计数 |
| DNS / 路由规则设置页暂未接入内核 | 见 §7，请在订阅里配置 |
| 上游模式切换需重启隧道 | 配置在启动时生成 |
