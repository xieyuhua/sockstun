## 1. 两种上游（二选一）

| 上游 | 何时生效 | 说明 |
| --- | --- | --- |
| **订阅** | 未启用任何手动服务器时 | 可保存多个订阅，节点合并成一个池 |
| **手动服务器** | 在「服务器」页点「启用」后 | 优先级高于订阅，**启用即忽略订阅** |

两者互斥：在订阅页点「使用」选用节点会**自动取消**手动服务器的启用；反之，启用某台服务器后订阅节点不再参与。

## 2. 快速上手

### 2.1 用订阅（推荐）

1. **设置 → 订阅配置 → 新增订阅**，填地址（或直接粘贴 base64 / 备份文本）→ 返回。
2. 在 **设置 → 订阅配置** 点 **更新订阅**（普通 YAML 或 base64 均可）。
3. 回到 **订阅** 页点 **测速全部**，等列表出现节点（见 §5.1）。
4. 在想用的节点上点 **使用**。
5. 回 **首页** 点 **连接** → 系统 VPN 授权框点确定。

### 2.2 只用手动服务器

1. 底部 **服务器 → 新增服务器**，填名称（可选）/ 协议 / 地址 / 端口 → 保存。
   - 地址栏可以直接**整段粘贴** `socks5://用户名:密码@主机:端口`，App 会自动拆出主机与端口（内嵌端口优先于表单里的端口）。
2. 在列表里点该服务器的 **启用**（会忽略订阅）。隧道**已连接**时会自动重建配置立即生效。
3. 回首页点 **连接**。

> Android 13+ 首次会请求**通知权限**，请允许，否则看不到常驻通知。

## 3. 权限

| 权限 | 用途 | 何时 |
| --- | --- | --- |
| VPN（系统弹窗） | 建立 TUN 接口 | 第一次点连接 |
| 通知 `POST_NOTIFICATIONS` | 常驻通知与流量 | Android 13+ 首次启动 |
| 开机自启 `RECEIVE_BOOT_COMPLETED` | 上次是连接状态时，重启后自动恢复 | 无弹窗 |

无通讯录 / 短信 / 定位等敏感权限。

## 4. 首页

底部 5 个标签：**首页 · 订阅 · 服务器 · 规则 · 设置**（其它 4 项各自打开独立页面）。

首页内容：

| 区块 | 说明 |
| --- | --- |
| 状态卡片 | 未连接 / 已连接 / 连接失败；失败时卡片变红并显示原因，同时弹一次 Toast |
| 连接 / 断开 | 主按钮。首次连接会拉起系统 VPN 授权框，授权后启动服务；断开时回收 TUN 与内核 |
| 当前节点 | 显示**内核真正在用的节点**，而不是"点了但没生效"的愿望值；无节点时显示「订阅默认节点 / 未配置节点」 |
| 流量卡片 | 实时 / 本次 / 累计，带「重置累计」（1.5 秒刷新一次） |

通知栏：标题 = 当前节点，正文 = 实时速率；展开可见 节点 + 实时 + 本次 + 累计，以及「断开」按钮。

> 首页与通知栏显示的是内核的**事实**：手动上游时是 `协议 · 名称`，订阅模式且隧道已连接时来自内核的当前选择。详见 [订阅与测速](订阅与测速.md) §3。
>
> 早期版本首页有「配置档」左右切换器。当前界面**不再提供**该入口，实际只使用第 0 档；底层多档存储仍在（见 §12）。

## 5. 订阅

右上角菜单只有两项：**使用说明**、**备份管理**。多订阅地址的新增 / 修改 / 删除 / 启用都在 **设置 → 订阅配置**；本页只负责展示合并后的节点与测速。

### 5.1 测速

| 操作 | 说明 |
| --- | --- |
| **测速全部**（右下 FAB） | 对**当前国家/协议筛选范围内**的全部节点做真实转发测速 |
| **单节点「测速」** | 只测该节点；批量进行中该按钮会置灰 |

要点：

- **范围 = 你看到的**：选「全部」就测全部节点，选某国就测该国节点；统计行 `可用 / 不可用 / 共 N 个`、`显示 N 个` 也都以当前筛选为准。
- **同一时间只跑一轮**：上一轮没结束时再点会提示「上一轮测速还没结束」，不会叠加。
- **不设总时间上限**：整轮只受「延迟测试超时」约束，几千个节点也能一轮测完；耗时 ≈ 各节点探测时间之和（内核动作桥一次只能处理一个探测）。
- **大部分可用节点是并发量完的**：内核会按组并发拨测（分组快测），几秒到几十秒就能把几百个**可用**节点量完；随后对「端口都连不上」的节点做一次本机 TCP 预筛（只判死、不判活），剩下的失败/未命中节点才逐个串行探测，每个约等于「延迟测试超时」。
- **卡住会自动结束**：连续 `max(30 秒, 延迟测试超时+15 秒)` 没有新结果时判定卡住，本轮结束、按钮恢复，剩余按「未测速」处理并提示看日志。
- **后台继续跑**：中途切页面再回来，进度条与已测结果都还在；结果边测边保存。
- **颜色**：绿色 `123 ms` = 可用；红色「不可用」= 内核无法经该节点转发；灰色「未测速」= 这一轮没能得到结论。

### 5.2 节点列表

- **国家 / 地区筛选**：顶部一排可横向滑动的标签（`全部` + 各国，数字为该国 `可用/总数`）。选中某国会把**隧道的节点池**也限制到该国；隧道**已连接**时会**自动重连**应用新节点池。
- **协议筛选**：下拉框按协议（ss / vmess / trojan…）过滤，括号里的计数是当前筛选范围内**列表实际显示的节点数**。
- **排序**：按延迟（快 → 慢）。
- **显示范围**：默认只显示**可用**节点。要看不可用 / 未测速的节点：打开 设置 → 订阅 → **显示不可用节点**（它们排在列表最下方）。
- **使用**：隧道未连接时只是记住节点（下次启动生效）；隧道已连接时**立即切换**，无需重连。选中节点高亮显示「使用中」。
- **长按节点** → 弹出菜单：
  - **添加到服务器列表**：只保存，订阅仍是上游；到「服务器」页点「启用」才会用它。
  - **添加并启用（忽略订阅）**：立即作为上游；隧道已连接时自动重连。
  - 非 SOCKS5 协议会连**原始 clash 定义**一起搬运（uuid / sni / ws-opts 等参数不丢）；同名同地址不会重复添加。
  - 若提示「无法还原该节点的原始定义」：说明订阅原文里找不到它（多为订阅刚更新过），先「更新订阅」再试。日志里会留 `服务器: 无法还原节点「…」的原始定义 · type=… · subId=… · 该订阅原文=N 字节`。
- **自动选择**（开关）：打开后由内核 `url-test` 定时测速、自动用最快节点，此时点「使用」只作提示（节点不会被固定）。
  - 测速间隔与测试地址：设置 → 延迟测试配置 → 测速配置 页。

### 5.3 备份 / 导入 / 迁移

**备份**把"当前可用的节点"固化成本地内容：机场换域名、封号、订阅被清空，都还能继续用同一批节点。

入口有两个，能力一致：

- 订阅页右上角菜单 → **备份管理**
- 设置 → 备份 → **备份管理**

备份管理页分上下两块：

| 区块 | 能做什么 |
| --- | --- |
| **订阅备份** | 「备份当前可用节点」（按钮上带可备份数量）；历史列表每条可**恢复（覆盖当前配置）**或**删除** |
| **服务器备份** | 「备份服务器列表」（把当前全部手动服务器连同"当时启用中的那台"整体存下来）；历史列表同样可**恢复**或**删除**，恢复时替换全部服务器并恢复当时的启用状态 |

行为细节：

- 订阅备份 = 把**所有可用节点**（延迟 ≥ 0）连同各自**原始 clash 定义**存成一条**本地订阅**（名字形如「备份 11-06 14:20」）；原文里找不到的节点会跳过，Toast 会报数量。
- 备份完会立刻询问是否 **应用此备份（覆盖当前订阅）**：一键启用它、停用其它订阅，隧道已连接时立即重建配置。
- 新备份默认**停用**，否则会和来源订阅一起合并、节点翻倍。要用时在「订阅配置」打开开关，或走上面的「覆盖当前配置」。
- 服务器备份只存本地，不与订阅备份混在一起，也不上传 WebDAV。
- 备份的是**节点 / 服务器的原始定义**（uuid / sni / ws-opts 等参数都在），不是延迟数字——换网络后延迟会重新测。

**WebDAV 远程备份**（设置 → 备份）：

| 项 | 说明 |
| --- | --- |
| WebDAV 远程备份（开关） | 打开**且**地址非空时，「备份当前可用节点」会**额外**上传一份到云端；上传失败只提示，本地记录仍在，不会丢数据 |
| WebDAV 配置 | 弹窗里填 地址 / 用户名 / 密码 / 远程目录，可先「测试连接」验证读写权限再保存 |
| 从 WebDAV 导入 | 在 **设置 → 订阅配置** 的菜单里：列目录 → 选一个 → 下载 → 落成本地订阅 |

> **云端目录要先存在**：WebDAV 不能自动建多级目录，请先在网盘里建好「远程目录」，或留空直接放进地址根下。各家根地址不同（Nextcloud 形如 `https://域名/remote.php/dav/files/用户名/`、坚果云形如 `https://dav.jianguoyun.com/dav/`）。

**导入 / 迁移**（设置 → 订阅配置 的菜单，或长按订阅列表弹出的「订阅工具」）：

| 操作 | 说明 |
| --- | --- |
| **导入订阅内容** | 粘贴 **base64**、含 `proxies:` 的 **clash.yml**，或此前「复制全部节点」得到的文本 → 存成本地订阅 |
| **新增订阅** | 填 `http(s)` 链接就是网络订阅；粘贴 base64 / 含 `proxies:` 的明文则自动存成本地订阅 |
| **复制全部地址** | 每行一个订阅地址（本地条目没有地址，自动跳过） |
| **复制全部节点** | 把所有订阅（含备份）的节点去重合并成一份 `proxies:` 文本，可直接再导入 |
| **从 WebDAV 导入** | 见上 |

注意：

- 备份 / 导入产生的都是**本地订阅**：「更新订阅」会**跳过**它们（内容已在本地，去拉只会覆盖），「编辑」里也没有地址可填。

### 5.4 订阅相关常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 「未能从订阅解析到任何节点」 | 订阅不是含 `proxies:` 列表的标准 clash.yml；用浏览器打开确认能看到 `proxies:` |
| 更新后列表是空的 | 列表只显示可用节点，先点「测速全部」 |
| 节点全是「不可用」 | 手机到该节点的网络不通，或测速目标不可达；换节点 / 换网络，或把「测速地址」换成自己可达的 URL |
| 一大批节点同时变成「不可用」 | 若日志里出现「本轮 N 个『不可用』全部来自『无响应』」，通常是**内核 / 控制接口**的问题而非节点全死：先断开重连一次；也可以把「无响应判为不可用」关掉，让这类情况退回「未测速」 |
| 换了节点但没变化 | 是否点了「使用」；自动选择开着时以内核测速为准 |
| 测速很慢 | 失败节点只能逐个串行探测；把「测速地址」换成稳定可达的地址，或先按国家缩小范围 |

## 6. 服务器（手动上游）

管理多套手动节点，每台可独立新增 / 修改 / 删除。

| 项 | 说明 |
| --- | --- |
| 名称 | 选填，留空则显示 `地址:端口` |
| 协议 | SOCKS5，或其它协议（需粘贴 clash 格式的完整节点定义） |
| 服务器地址 / 端口 | 地址 + 端口；地址栏支持整段粘贴链接，自动抽取主机与端口 |
| 用户名 / 密码 | SOCKS5 选填 |
| 节点配置 | 非 SOCKS5 时显示，粘贴 clash 格式的完整节点定义（`- {name:..., type:...}`）。下方有 **复制 JSON / 复制 Clash / 粘贴** 三个按钮：复制可任选 JSON 或 clash 两种写法，粘贴**两种格式都兼容** |

操作：

- **启用**：点列表里的「启用」，该台即成为上游并**忽略订阅**（显示「启用中」）。隧道**已连接**时立即重建配置生效，不用手动重连。
- **编辑启用中的那台**：同样会在已连接时自动重连，新地址 / 端口 / 账号即时生效。
- **取消启用**：到订阅页选一个节点，或删除该台服务器。
- 同一时刻只有一台生效。
- **测速**：单台「测速」或右下 FAB「测速全部」（全部测完会弹一次结果汇总：共测几台 / 可用几台 / 不可用几台）。延迟结果（含「不可达」）会**写入存储**，下次进入页面直接显示。
- **长按某台**：弹出该台的菜单——**编辑 / 复制原文 / 复制为 JSON / 删除**（行内保留「测速」与「启用」按钮）。
- 隧道连接中且当前是「部分应用」却没勾选任何应用时，启用服务器会额外提示——这种状态下没有任何流量会进隧道。

> 上游相关改动都写进启动时生成的 `config.yaml`。App 已在「启用 / 编辑启用中的服务器」时自动重建，其它时刻若要强制重来，断开再连接即可。

## 7. 规则（分流 → DNS → 路由规则）

按生效顺序分三块。

### 7.1 分流作用域（最前置）

| 项 | 说明 |
| --- | --- |
| **全局**（默认） | 所有应用流量进隧道（本 App 自身除外） |
| **部分应用** | 只有勾选的应用进隧道，其余直接走原网络。点 **应用** 进入勾选列表（只列声明了联网权限的应用，可搜索） |
| **IPv4 / IPv6** | 隧道地址族开关 |
| **UDP relay over TCP** | 勾选后手动 SOCKS5 节点不再申请 UDP ASSOCIATE，只走 TCP CONNECT——适用于只转发 TCP 的 frp / 内网穿透 |

> ⚠️ **两层路由，先判作用域**：「全局 / 部分应用」决定**哪些 App 的流量进隧道**（VPN 作用域）；进隧道之后才由分流策略决定代理还是直连。**被作用域排除的应用由系统直接联网，路由规则对它完全不生效。**
>
> ⚠️ **部分应用但没勾选任何应用**：没有任何流量进隧道（等于不代理），规则页会显示红色警告。
>
> 运行中切换「全局 / 部分应用」会自动**重连隧道**。

### 7.2 DNS

| 项 | 说明 |
| --- | --- |
| **远程 DNS**（默认开） | 内核用 `fake-ip` 模式：域名以**域名形式**交给代理端解析（SOCKS5 的域名 CONNECT），因此**内网域名可由代理侧的内网 DNS 解析**，本机不必解析成功；此时本地 DNS 地址框禁用 |
| **DNS IPv4 / DNS IPv6** | 关闭远程 DNS 后生效：内核切到 `redir-host`，用你填的 DNS 拿真实 IP，并让 DNS 查询本身也按规则走隧道（`respect-rules`），否则手机物理网卡到不了内网 DNS |

- 只接受**纯 IP**：带 `https://`、带端口、非法地址会被忽略并回退公网 DNS（`223.5.5.5` / `119.29.29.29`）。
- 同一组 DNS 会同时写进内核 `dns:` 段、VPN 网卡的 DNS 与 TUN 启动参数，避免"系统走公网、内核走内网"的割裂。

### 7.3 路由规则

App 自己生成 mihomo 的 `rules:` 段交给内核，**订阅自带的 `rules` / `rule-providers` / 代理组会被忽略**（订阅只贡献节点）。

- **分流策略**（三选一）：
  - **规则模式**（默认）：按下方规则分流，未命中的走「未命中默认」。
  - **全局代理**：所有流量走代理，规则列表不生效。
  - **全局直连**：所有流量直连，规则列表不生效。
- **未命中默认**：规则模式下的兜底——命不中的流量走代理还是直连。
- **规则类型 → 动作 → 值 → 添加**：

  | 类型 | 含义 | 示例 |
  | --- | --- | --- |
  | 域名后缀 | 该域名及其所有子域 | `google.com` |
  | 域名(精确) | 完全匹配 | `www.google.com` |
  | 域名关键字 | 域名含该子串即命中 | `google` |
  | 域名分类(GeoSite) | geosite 标签 | `openai` |
  | IP | 单个 IP | `1.2.3.4` |
  | IP 段 | CIDR（v4/v6 均可） | `10.0.0.0/8` |
  | GeoIP 国家 | 两位国家码 | `CN` |
  | 进程名 | App 包名 | `com.android.chrome` |
  | 进程路径 | 可执行路径 | `/system/bin/ping` |
  | 目标端口 | 端口或范围 | `443` / `1000-2000` |
  | 源端口 | 端口或范围 | `12345` |
  | 网络类型 | `tcp` / `udp` / `tcp,udp` | `udp` |

- 每条规则可选 **Proxy / Direct**；列表里可删除。
- 命中国家码 / GeoSite 的规则需要内核的 geoip/geosite 数据库，首次使用时会自动下载（走 jsdelivr 镜像）。

> 隧道**连接中**时规则编辑控件会置灰（改动需**重新连接**生效）。

## 8. 设置

设置页按分组排列：

| 分组 | 内容 |
| --- | --- |
| **连接** | 连接信息（弹窗：状态 / 节点 / 服务器 / 本次与累计流量）、应用（按应用勾选，同 §7.1）、规则（进入规则页）、活跃连接、最近请求、控制接口密钥（`clash-api` 令牌，可查看 / 复制 / 重置，重置需重启隧道生效） |
| **局域网代理** | 允许局域网连接（开关）、代理端口（默认 `7890`，1024–65535） |
| **订阅** | 订阅配置（多订阅 / 本地备份的增删改启用、导入、复制全部、长按「订阅工具」）、显示不可用节点（默认关） |
| **延迟测试配置** | 一行入口，进入 **测速配置** 二级页（见下表） |
| **备份** | WebDAV 远程备份（开关）、WebDAV 配置、备份管理（同 §5.3） |
| **通用** | 日志（「记录日志」开关 + 查看日志，**下次连接生效**）、配置文件 config.yaml（查看 / 编辑，可开启「使用自定义配置」不自动生成）、主题（5 套：霓虹绿（默认）/ 赛博青 / 午夜紫 / 琥珀 / 纸白） |
| **关于** | 版本（版本号、版本码、内核版本、支持的 ABI） |

**测速配置页**（设置 → 延迟测试配置）：

| 项 | 说明 |
| --- | --- |
| 测速测试地址 | 测速与 `url-test` 组使用的目标，默认 `http://www.gstatic.com/generate_204`；留空恢复默认。**每个节点只探这一个目标**，所以填一个稳定可达的地址能显著减少误判 |
| 延迟测试超时 | 单次探测的等待秒数，默认 5，范围 1–30。这是**唯一**的时间旋钮：超时 / 失败即判不可用 |
| 无响应判为不可用 | 默认开。探测在超时内**完全没有响应**（内核 / 控制接口不回包）→ 判「不可用」；关闭则更保守，记为「未测速」，只有内核明确报失败才判不可用 |
| 自动测速间隔 | `url-test` 重新测速的间隔，默认 5 分钟，范围 1–1440 |
| 未连接时内核测速 | 默认开。未连接 VPN 时提前加载测速内核，让点「测速」后立刻开始；关掉只是不预加载，点测速时仍会按需加载（首次慢几秒） |

> 代理端口 / 允许局域网 / 测速地址 / 自动测速间隔等都会写进启动时生成的配置，改完**需重新连接**生效（页面会提示）。
>
> 早期版本的「每节点测速上限」已移除：每个节点只探一次，时间由「延迟测试超时」决定，不再有第二个总时限。

## 9. 活跃连接 与 最近请求

### 9.1 活跃连接

内核对**当前正在打开**的连接（经代理的）实时列表：

- 目标地址、命中规则 · 节点链、来源应用、**连接开始时间**、上行 / 下行。
- 顶部摘要：条数 + 上行 / 下行合计；支持搜索。
- **断开全部**：在服务进程里直接调内核动作并立刻清空列表（不等下一拍）。
- 每 1.5 秒刷新一次。

### 9.2 最近请求

隧道运行期间，**已经关闭**的连接会作为「最近请求」记录下来：

- 目标地址、匹配规则、节点链、来源应用、持续时间、**请求时间**、上行 / 下行。
- 支持搜索；**清空**可删除全部记录（即使当前列表为空也能点）。
- 点某一行可看完整详情。
- 记录有上限、按流量排序。

## 11. 常见故障速查与日志

| 现象 | 优先检查 |
| --- | --- |
| 点连接提示内核加载失败 | 多为 ABI / 安装包问题，重装 |
| 更新订阅失败 | 订阅地址能否在浏览器打开；是否 HTTP 非 200 |
| 解析不到节点 | 订阅是否含 `proxies:` |
| 已连接但不代理 | 规则页作用域是否为「部分应用但未选应用」；分流策略是否「全局直连」 |
| 连上但访问不到内网地址 | 是否启用了正确的手动上游（日志 `upstream:` 行会写出当前上游与未命中规则去向）；DNS 是否指向能解析内网的内网 DNS（需关闭「远程 DNS」）；目标内网网段是否与隧道地址冲突（隧道用 `100.64.0.1`，已避开常见私网段） |
| 连上但打不开网页 | 换个节点；确认节点测速为可用 |
| 换了节点但没变化 | 是否点了「使用」；自动选择开启时以内核测速为准 |
| 活跃连接 / 最近请求为空 | 需隧道运行中；最近请求需要先有经代理的连接产生 |
| 通知不显示 | Android 13+ 通知权限；通知渠道是否被静音 |
| 看不到日志 | 日志开关**下次连接**才生效 |

### 11.1 日志：出问题时先抓它

日志是排查「测速异常 / 连上不走流量 / 节点全不可用」的**唯一证据链**。它**默认开着**；如果之前关过：设置 → 通用 → 日志 → 打开「记录日志」，**下次连接生效**。

**怎么看**：设置 → 通用 → 日志 → 进入日志页。

- 默认「自动刷新」开着（相当于 `tail -f`）；手指碰一下正文会**暂停自动刷新**，方便长按选中，读完点「复制」可整份拷走。
- 页面顶部若显示「日志已关闭（下次连接生效）」，说明开关没开或还没重连。
- 日志文件在应用私有的 `cache/tproxy.log`（`/data/data/com.tunvpn/cache/tproxy.log`），普通用户拿不到，用页面里的「复制」即可。
- `=== tunVPN start (pid …)` 那一行标志着一次新的连接会话，从它往后看。

**测速问题**：点「测速全部」后，把从 `=== 测速开始` 到 `=== 测速结束` 的**整段**贴出来。它能区分「节点真死」与「测试没跑起来」：

| 日志行 | 说明 |
| --- | --- |
| `测速: 内核 /proxies 共 N 项，可测节点 M 个` | M = 0 说明配置里**真的**没有可测节点（不是节点都坏了） |
| `测速自检：可用 xxx ms` | 批量开始前的单线程自检；**没有这一行或它失败**，就是桥 / 控制接口的问题，与节点无关 |
| `测速: 分组快测命中 x/y 个节点` | 内核并发量完的部分；命中越多，后面的串行尾巴越短 |
| `测速: TCP 预筛 … 判死 n 个` | 本机连不上端口的节点被提前剔掉（只判死，不判活） |
| `bridge:` / `delay:` 开头 | 桥或参数层面的问题（内核拒参、换形状、无回包），同样不是节点判定 |
| `测速结果: <节点名> … -> 不可用(-2)` | 每个被判为不可用的节点一行 |
| `本轮 N 个「不可用」全部来自「无响应」` | 节点多半没死，是内核 / 控制接口沉默；可先断开重连，或关掉「无响应判为不可用」 |

**连上但不走流量**：看这几类行——

- `upstream:`：当前上游（手动服务器 / 订阅节点池）与未命中规则的默认去向——一眼区分"内核还在用旧配置"和"流量被判成直连"。
- `config:` / `routing:`：代理端口、节点数、分流策略、兜底目标。
- `controller:` / `listen:` / `clash-api:`：控制接口有没有起来、绑在哪个地址。

## 12. 已知限制

| 限制 | 说明 |
| --- | --- |
| 测速是内核真实转发延迟 | 代表节点能否连通与链路快慢，**不代表实际带宽** |
| 订阅自带的 `rules` / `rule-providers` / 代理组不生效 | 路由由 App「规则」页统一接管，订阅只贡献节点 |
| 上游 / 作用域 / DNS / 规则 / 端口等改动需重连 | 配置在启动时生成；启用服务器、编辑启用中的服务器、选节点、切国家这几处已自动重建 |
| 国家筛选会限制整个隧道节点池 | 已连接时切换国家会自动重连；未连接时下次启动生效 |
| 只显示一档配置 | 底层按档存储、上限 13 档仍在，但界面未提供切换 / 新增 / 重命名入口，日常只有第 0 档 |
| 首页 / 通知栏显示的是**内核真正在用的节点** | 选中节点是"愿望"；若它不在运行配置里，服务会重建配置把它真正切过去 |

## 附录 A：自建 SOCKS5 上游服务器

不使用订阅时，可以把「服务器」页里的某台 SOCKS5 作为上游。下面是一份可直接用的参考实现（[hev-socks5-server](https://github.com/heiher/hev-socks5-server)）：

```bash
git clone --recursive https://github.com/heiher/hev-socks5-server
cd hev-socks5-server
make

hev-socks5-server conf.yml
```

```yaml
main:
  workers: 4
  port: 1080
  listen-address: '::'

misc:
  limit-nofile: 65535
```

- 任何实现了 RFC1928 中 CONNECT 与 UDP-ASSOCIATE 的 SOCKS5 服务器都可以。
- 只转发 TCP 的实现（frp / 内网穿透）请在规则页勾选 **UDP relay over TCP**，App 会给该节点写 `udp: false`，避免 UDP 走一条永远不通的路。
