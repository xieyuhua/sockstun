# ProTun 用户手册

面向使用者的完整说明：从安装到日常使用，以及常见问题排查。实现细节见 [开发与架构](开发与架构.md)。

引擎是内嵌的 **mihomo（Clash.Meta）**，所以订阅里的 vmess / vless / trojan / shadowsocks / hysteria2 / tuic / socks5 等节点**都能用**，不限于 SOCKS5。

---

## 1. 两种上游（二选一）

| 上游 | 何时生效 | 说明 |
| --- | --- | --- |
| **订阅** | 未启用任何手动服务器时 | 可保存多个订阅，节点合并成一个池 |
| **手动服务器** | 在「服务器」页点「启用」后 | 优先级高于订阅，**启用即忽略订阅** |

两者互斥：在订阅页点「使用」选用节点会**自动取消**手动服务器的启用；反之亦然。

---

## 2. 快速上手

### 2.1 用订阅（推荐）

1. 底部 **订阅** → 右上角 ⋮ → **订阅配置** → 「新增订阅」填地址 → 返回。
2. 点 **拉取订阅**（普通 YAML 或 base64 均可）。
3. 点 **测速全部**，等列表出现节点（见 §6）。
4. 在想用的节点上点 **使用**。
5. 回 **首页** 点 **连接** → 系统 VPN 授权框点确定。

### 2.2 只用手动服务器

1. 底部 **服务器** → **新增服务器** → 填名称（可选）/ 协议 / 地址 / 端口 → 保存。
2. 在列表里点该服务器的 **启用**（会忽略订阅）。
3. 回首页点 **连接**。

> Android 13+ 首次会请求**通知权限**，请允许，否则看不到常驻通知。

## 3. 权限

| 权限 | 用途 | 何时 |
| --- | --- | --- |
| VPN（系统弹窗） | 建立 TUN 接口 | 第一次点连接 |
| 通知 `POST_NOTIFICATIONS` | 常驻通知与流量 | Android 13+ 首次启动 |
| 开机自启 `RECEIVE_BOOT_COMPLETED` | 上次是连接状态时，重启后自动恢复 | 无弹窗 |

无通讯录 / 短信 / 定位等敏感权限。

## 4. 首页

底部 5 个标签：**首页 · 订阅 · 服务器 · 规则 · 设置**（其它 4 项会打开各自的页面）。

首页内容：

- **状态卡片**：三种状态——未连接 / 已连接 / 连接失败（失败时卡片变红并显示失败原因，同时弹一次 Toast）。
- **连接 / 断开** 按钮。
- **当前节点**：显示正在使用的节点；无节点时显示「订阅默认节点 / 未配置节点」。
- **配置档名**：左右箭头 `◀ / ▶` 切换，长按可重命名 / 新增 / 删除。
- **流量卡片**：实时 / 本次 / 累计，带「重置累计」。

通知栏：标题 = 当前节点，正文 = 实时速率，展开可见节点 + 实时 + 本次 + 累计，以及「断开」按钮。

> 连接状态下不能切换配置档，先断开。

## 5. 订阅

顶部显示当前默认订阅。右上角菜单：**订阅配置**（多订阅管理）、**使用说明**。

节点列表：

- **拉取订阅**：更新全部启用的订阅，节点合并去重成一个池。
- **测速全部**（右下 FAB）：对**当前国家/地区筛选范围内的全部节点**做真实转发测速（选「全部」即全部节点，选某国即该国全部节点）。运行期间 FAB 置灰，卡片里出现**进度条**，顶部显示 `测速中 x/y（n%）`；单个节点的「测速」同样会显示 1/1 的进度。
  - **同一时间只跑一轮**：上一轮没结束时再点会提示「上一轮测速还没结束」，不会叠加（叠加会导致计数错乱、界面卡死）。
  - **有时间上限**：一轮测速最多跑 `min(20 分钟, max(3 分钟, (每节点上限+3 秒) × 节点数))`——桥是单回调串行的，测速耗时≈各节点探测时间之和，所以节点多时确实要等；超过上限的节点会明确标成「未测速」并提示剩余数量，不会一直转下去。批量测速时单目标超时会被自动收紧（最长 4 秒/目标，失败即转一次救援探测），避免个别死节点拖很久。
  - **卡住会自动结束**：连续 `max(60 秒, 每节点上限+15 秒)` 没有任何新结果时，判定"卡住"，本轮直接结束（进度拉满、按钮恢复），剩余按「未测速」处理并提示看日志。
  - **统计数字以当前筛选为准**：`可用 / 不可用 / 共 N 个` 与 `显示 N 个` 都是**当前国家+协议筛选范围内**的数字，不是整份订阅的总数。
  - **为什么"测速全部"不快**：测速要经内核逐个节点发真实请求，而内核的动作接口一次只处理一个请求，所以总耗时≈各节点耗时之和。页面会显示 `剩余约 N 秒` 估算；可用节点通常几百毫秒一个，失败节点每个约 12 秒（4 秒首选目标 + 8 秒救援探测）。
  - **测速在后台跑**：中途切到别的页面再回来，进度条和已测结果都还在（继续显示真实进度）；已测出的结果会边测边保存，不会因为离开页面而丢。
- **单个「测速」**：只测该节点。
- **节点列表默认只显示「可用」节点**（已有延迟结果）。未测速 / 不可用的节点不显示，先点「测速全部」把它们测出来。
  - 绿色 `123 ms` = 可用；红色「不可用」= 内核无法经该节点转发；灰色「未测速」。
  - 想让列表**也显示不可用 / 未测速节点**：打开 设置 → 订阅 → **显示不可用节点**（此时它们排在列表最下方，可用节点仍按延迟在最前）。
  - 结果会保存，下次打开还在。
- **国家 / 地区筛选**：顶部一排可横向滑动的国家小标签（`全部` + 各国，数字为该国的 `可用/总数`）。选中某国会把**隧道的节点池**也限制到该国；隧道**已连接**时选它会**自动重新连接**应用（新配置只含该地区节点），未连接时下次启动生效。
- **协议筛选**：下拉框按协议（ss / vmess / trojan…）筛选，计数为当前国家下的可用数。
- **排序**：按延迟（快→慢）。
- **使用**：
  - 隧道**未连接**时：记住节点，下次启动隧道生效。
  - 隧道**已连接**时：**立即切换**，无需重连。
  - 选中节点高亮显示「使用中」。
- **自动选择**（开关）：打开后由内核定时测速、自动用最快节点，此时点「使用」只是提示（节点不会被固定）。
  - 测速间隔：**设置 → 自动测速间隔**（分钟，1–1440）。
  - 测试地址：**设置 → 测速测试地址**。
- **长按节点**：把该节点复制到「服务器」列表，方便单独固定使用。

### 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 「未能从订阅解析到任何节点」 | 订阅不是含 `proxies:` 列表的标准 clash.yml；用浏览器打开确认能看到 `proxies:` |
| 拉取后列表是空的 | 列表只显示可用节点，先点「测速全部」 |
| 节点全是「不可用」 | 手机到该节点的网络不通，或测速目标不可达；换个节点 / 网络，或到设置里更换测速测试地址 |
| 换了节点但没变化 | 是否点了「使用」；自动选择开着时以内核测速为准 |

## 6. 服务器（手动上游）

管理多套手动节点，每台可独立新增 / 修改 / 删除：

| 项 | 说明 |
| --- | --- |
| 名称 | 选填，留空则显示 `地址:端口` |
| 协议 | SOCKS5，或其它协议（需粘贴 clash 格式的完整节点定义） |
| 服务器地址 / 端口 | 地址 + 端口 |
| 用户名 / 密码 | SOCKS5 选填 |

- **启用**：点列表里的「启用」，该台即成为上游，并**忽略订阅**（显示「启用中」）。
- **取消启用**：到订阅页选一个节点，或删除该台服务器。
- 同一时刻只有一台生效。

> 换服务器 / 改参数后需要**重启隧道**才生效。

## 7. 规则（分流 → DNS → 路由规则）

按生效顺序分为三块。

### 7.1 分流作用域（最前置）

- **全局**（默认）：所有应用流量进隧道（本 App 自身除外）。
- **部分应用**：只有勾选的应用进隧道，其余直接走原网络。点 **应用** 进入勾选列表（只列出声明了联网权限的应用，可搜索）。
- **IPv4 / IPv6**、**UDP relay over TCP**：隧道协议开关。

> ⚠️ **两层路由，先判断作用域**：「全局 / 部分应用」决定**哪些 App 的流量进隧道**（VPN 作用域，最前置）；进隧道之后，才由下面「分流策略」决定代理还是直连。**被作用域排除的应用由系统直接联网，路由规则对它完全不生效。**
>
> ⚠️ **部分应用但没勾选任何应用**：没有任何流量进隧道（等于不代理）。规则页会在该情况下显示红色警告。
>
> 运行中切换「全局 / 部分应用」会自动**重连隧道**以立即生效。

### 7.2 DNS

- **远程 DNS**：由代理解析域名（开启后本地 DNS 地址输入框禁用）。
- **DNS IPv4 / DNS IPv6**：本地 DNS 服务器地址。

### 7.3 路由规则

App 自己生成 mihomo 的 `rules:` 段交给内核，**订阅自带的 `rules` / `rule-providers` / 代理组会被忽略**（订阅只贡献节点）。分流策略完全由本页决定。

- **分流策略**（顶部下拉，三选一）：
  - **规则模式**（默认）：按下方规则分流，未命中的走「未命中默认」开关。
  - **全局代理**：所有流量走代理，规则列表不生效。
  - **全局直连**：所有流量直连，规则列表不生效。
- **未命中默认**：规则模式下的兜底——命不中的流量走代理还是直连。
- **规则类型 → 动作 → 值 → 添加**：

  | 类型 | 含义 | 示例 |
  | --- | --- | --- |
  | 域名后缀 | 该域名及其所有子域 | `google.com` |
  | IP | 单个 IP | `1.2.3.4` |
  | IP 段 | CIDR（v4/v6 均可） | `10.0.0.0/8` |
  | 域名关键字 | 域名含该子串即命中 | `google` |
  | GeoIP 国家 | 两位国家码 | `CN` |
  | 进程名 | App 包名 | `com.android.chrome` |
  | 域名(精确) | 完全匹配 | `www.google.com` |
  | 域名分类(GeoSite) | geosite 标签 | `openai` |
  | 进程路径 | 可执行路径 | `/system/bin/ping` |
  | 目标端口 | 端口或范围 | `443` / `1000-2000` |
  | 源端口 | 端口或范围 | `12345` |
  | 网络类型 | `tcp` / `udp` / `tcp,udp` | `udp` |

- 每条规则可选 **Proxy / Direct**；列表里可删除。
- 命中国家码 / GeoSite 的规则需要内核的 geoip/geosite 数据库，首次使用时会自动下载（走 jsdelivr 镜像）。

> 隧道**连接中**时规则编辑控件会置灰（改动需**重新连接**生效）。改完断开重连即可。

## 8. 设置

设置页按分组排列：

**连接**

| 项 | 说明 |
| --- | --- |
| 连接信息 | 弹窗显示实时状态、节点、服务器、本次 / 累计流量 |
| 应用 | 进入按应用勾选列表（同 §7.1） |
| 活跃连接 | 当前正在使用代理的连接（见 §9） |
| 最近请求 | 已关闭的代理请求记录（见 §9） |
| 控制接口密钥 | clash-api 鉴权令牌，可查看 / 复制 / 重置（重置需重启隧道生效） |

**局域网代理**

| 项 | 说明 |
| --- | --- |
| 允许局域网连接 | 开启后同网络其它设备可把本机当代理用 |
| 代理端口 | 默认 `7890`，范围 1024–65535 |

**订阅**

| 项 | 说明 |
| --- | --- |
| 订阅配置 | 多订阅地址：新增 / 修改 / 删除 / 启用 |
| 测速测试地址 | url-test 与手动测速探测的目标，默认 `http://www.gstatic.com/generate_204`，清空恢复默认 |
| 延迟测试超时 | 单次探测（一个目标）的超时秒数，默认 5，范围 1–30；批量测速时自动收紧到 4 秒 |
| 每节点测速上限 | 单个节点**全部尝试**（含**每次探测的等待**）的时间上限，默认 15 秒，范围 5–120。**严格生效**：会给内核的探测时间和本地等待都按剩余额度收紧。调小整轮明显更快，但慢节点更容易被判超时 |
| 无响应判为不可用 | 默认开。在该节点时限内**完全没有响应**（内核/控制接口不回包）→ 直接判「不可用」，这正是"超时 = 不可用"；关闭则更保守，这类情况记为「未测速」，只有内核明确报失败才判不可用 |
| 自动测速间隔 | url-test 重新测速的间隔，默认 5 分钟，范围 1–1440 |
| 未连接时内核测速 | 默认开。**未连接 VPN 时提前加载**测速内核，使点「测速」后立刻开始；关掉只是不预加载，点测速时仍会按需加载（首次慢几秒） |
| 显示不可用节点 | 默认关。开启后订阅列表同时列出**不可用（测速失败）**与**未测速**的节点；关闭则只显示可用节点 |

**通用**

| 项 | 说明 |
| --- | --- |
| 日志 | 开关「记录日志」+ 查看日志，**下次连接生效** |
| 配置文件 config.yaml | 查看 / 编辑生成的配置；可开启「使用自定义配置」不自动生成 |
| 主题 | 5 套配色（Neon Green / Cyber Cyan / Midnight Purple / Amber / Paper Light） |

**关于**

| 项 | 说明 |
| --- | --- |
| 版本 | 版本号、版本码、内核版本、支持的 ABI |

> 代理端口 / 允许局域网 / 测速地址 / 自动测速间隔等改动都写进启动时生成的配置，**需重新连接生效**。

## 9. 活跃连接 与 最近请求

### 活跃连接

内核对**当前正在打开**的连接（经代理的）实时列表：

- 目标地址、规则 · 节点链、来源应用、**连接开始时间**、上行 / 下行流量。
- 顶部摘要：条数 + 上行 / 下行合计。
- 支持搜索；**断开全部**按钮（`DELETE /connections`）。
- 每 1.5 秒刷新一次。

### 最近请求

隧道运行期间，**已经关闭**的连接会作为「最近请求」记录下来：

- 目标地址、匹配规则、节点链、来源应用、持续时间、**请求时间**、上行 / 下行。
- 支持搜索；**清空**按钮可删除全部记录。
- 点某一行可看完整详情。
- 记录上限有限、按流量排序。

## 12. 常见故障速查

| 现象 | 优先检查 |
| --- | --- |
| 点连接提示内核加载失败 | 多为 ABI / 安装包问题，重装 |
| 拉取失败 | 订阅地址能否在浏览器打开；是否 HTTP 非 200 |
| 解析不到节点 | 订阅是否含 `proxies:` |
| 已连接但不代理 | 规则页作用域是否为「部分应用但未选应用」；分流策略是否「全局直连」 |
| 连上但打不开网页 | 换个节点；确认节点测速为可用 |
| 换了节点但没变化 | 是否点了「使用」；自动选择开启时以内核测速为准 |
| 活跃连接 / 最近请求为空 | 需隧道运行中；最近请求需要先有经代理的连接产生 |
| 通知不显示 | Android 13+ 通知权限；通知渠道是否被静音 |
| 看不到日志 | 日志开关**下次连接**才生效 |

## 13. 已知限制

| 限制 | 说明 |
| --- | --- |
| 测速是内核真实转发延迟 | 代表节点能否连通与链路快慢，**不代表实际带宽** |
| 订阅自带的 `rules` / `rule-providers` / 代理组不生效 | 路由由 App「规则」页统一接管，订阅只贡献节点 |
| 上游 / 作用域 / DNS / 规则 / 端口等改动需重连 | 配置在启动时生成 |
| 国家筛选会限制整个隧道节点池 | 已连接时切换国家会自动重连应用；未连接时下次启动生效 |
| 首页 / 通知栏显示的是**内核真正在用的节点** | 选中节点是"愿望"；若该节点不在运行配置里，服务会重建配置把它真正切过去，界面在 1 秒内跟着变 |
