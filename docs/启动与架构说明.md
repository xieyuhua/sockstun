# SocksTun 启动流程与架构说明

本文档说明本项目的整体结构，以及应用从「点击启动」到「原生隧道运行」的完整链路，方便排查“连上了但没流量”之类的问题。

---

## 1. 应用入口与组件

| 组件 | 作用 | 所在进程 |
| --- | --- | --- |
| `MainActivity` | 首页：连接/断开按钮、配置档切换、左侧抽屉菜单 | 主进程 |
| `TProxyService` (`VpnService`) | 建立 VPN 接口、生成配置、拉起原生隧道 | **`:native` 独立进程** |
| `QSTileService` (`TileService`) | 系统快捷开关（下拉栏里的一键连接） | 主进程 |
| `ServiceReceiver` (`BroadcastReceiver`) | 监听 `BOOT_COMPLETED` 实现开机自启 | 主进程 |
| `ServerActivity` / `DnsActivity` / `RoutingActivity` / `AppListActivity` | 各项设置的独立页面 | 主进程 |
| `LogActivity` | 查看/开关运行日志 | 主进程 |
| 原生库 `libhev-socks5-tunnel.so` | 真正做 SOCKS5 / TProxy 转发的引擎 | `:native` 进程 |

> 注意：`TProxyService` 在清单中被声明为 `android:process=":native"`，因此原生隧道与日志重定向都发生在**另一个进程**里。跨进程共享的开关状态（`Enable` 等）用的是 `Context.MODE_MULTI_PROCESS` 的 `SharedPreferences`（`SocksPrefs`）。

---

## 2. 三条启动路径

### 2.1 桌面图标启动（最常用）
1. 点击启动图标 → `MainActivity.onCreate`。
2. 立即请求 VPN 权限：`VpnService.prepare(this)`，未授权则弹出系统授权框。
3. 构建首页 UI：状态卡片、连接/断开按钮、配置档名与上/下/菜单按钮。
4. 用户点「连接」(`button_control`)：
   - 先把 `Enable` 置为 `true`；
   - `startService(new Intent(this, TProxyService.class).setAction(ACTION_CONNECT))`；
   - 通知快捷开关刷新（`QSTileService.requestUpdate`）。
5. 若之前未授权 VPN，`onActivityResult` 里在授权成功后再拉起 `TProxyService`。

### 2.2 系统快捷开关（Quick Settings Tile）
- `QSTileService.onClick`：
  - 已连接 → 置 `Enable=false` 并 `startService(ACTION_DISCONNECT)`；
  - 未连接 → 若未授权 VPN 则先拉起 `MainActivity` 去要权限，否则直接 `startForegroundService(ACTION_CONNECT)`。

### 2.3 开机自启
- `ServiceReceiver` 收到 `BOOT_COMPLETED`：若 `prefs.getEnable()` 为真，直接 `startForegroundService(TProxyService, ACTION_CONNECT)`（未授权时先弹授权 Activity）。

> 三条路径最终都汇聚到 `TProxyService`，所以“启动逻辑”只写在一处，不会发散。

## 3. TProxyService 内部流程（核心）

`TProxyService.onStartCommand`：收到 `ACTION_DISCONNECT` 就停，否则进入 `startService()`。

`startService()` 按顺序做：

1. **读取配置**：`new Preferences(this)`，拿到当前选中配置档的所有参数。
2. **日志重定向（调试用）**：
   - 若 `LogEnabled` 为真，用 `android.system.Os.dup2` 把进程的 fd 1/2（stdout/stderr）重定向到 `getCacheDir()/tproxy.log`；
   - 并在文件开头写一行 `=== SocksTun log start (pid ...) ===` 作为标记；
   - 原生库用 `printf/fprintf` 打的 `[D]`/`[W]`/`[E]` 日志因此被落盘，可被 `LogActivity` 读取。
   - 若 `LogEnabled` 为假，则不重定向、不写日志。
3. **建立 VPN 接口**：`VpnService.Builder` 按配置拼装：
   - IPv4/IPv6 地址与路由（`addAddress` / `addRoute 0.0.0.0` 或 `::`）；
   - DNS：本地 DNS 或「远程 DNS」(`mapdns`)；
   - 全局模式或按应用放行（`addAllowedApplication` / `addDisallowedApplication` 排除自身）；
   - `builder.establish()` 拿到 TUN 的文件描述符 `tunFd`（若失败则 `stopSelf()`）。
4. **生成原生配置**：把参数写成 YAML 临时文件 `getCacheDir()/tproxy.conf`，大致结构：
   ```yaml
   misc:
     task-stack-size: <值>
   tunnel:
     mtu: <值>
     icmp: 'reply'
   socks5:
     port: <端口>
     address: '<服务器地址>'
     udp: 'tcp' | 'udp'
     udp-address: '<UDP 服务器地址>'   # 可选，留空则不生成
     username / password:              # 可选，都填了才生成
   mapdns:                            # 仅当“远程 DNS”开启
     address: 198.18.0.2
     port: 53
     network: 240.0.0.0
     netmask: 240.0.0.0
     cache-size: 10000
   ```
5. **拉起原生隧道**：
   ```java
   TProxyStartService(tproxy_conf_path, tunFd.getFd());
   ```
   这是 `System.loadLibrary("hev-socks5-tunnel")` 暴露的 native 方法，之后真正的转发在 `:native` 进程的后台线程里跑。
6. **常驻通知**：`startForeground(...)` 显示前台通知（Android 要求 VPN/前台服务必须有通知）。

`stopService()`：置 `Enable=false`、停前台、`TProxyStopService()`、关闭 `tunFd`，最后 `System.exit(0)` 结束 `:native` 进程（下次连接会重新拉起，日志文件也会重新生成）。

## 4. 配置体系（多配置档）

- 所有设置都保存在 `SharedPreferences`（`SocksPrefs`）里，按**配置档**隔离：每个档位用 `P<index>.xxx` 作为 key 前缀。
- 当前选中的档位由 `Selected` 决定；`ProfileCount` 记录档位数量（最多 `MAX_PROFILES = 13`）。
- 切换档位（首页 `◀ / ▶` 或长按配置名菜单）只改 `Selected`，不改动各档内容。
- 新增/重命名/删除档位在 `MainActivity` 的对话框里完成，删除会平移后续档位下标。
- 各设置页（`ServerActivity` 等）在 `onPause` 时把编辑内容写回当前档位，所以回到首页/连接时读取到的都是最新值。
- 首次启动会把旧的扁平 key 迁移进第 0 个档位（`Preferences.migrate()`）。

### 与“没流量”最相关的配置点
- **服务器地址 / 端口 / UDP 服务器地址**：地址与 UDP 地址各自独占一行，任选其一填写。UDP 地址留空 → 不生成 `udp-address`，由原生库自己决定 UDP 出口。
- **UDP 走 TCP**（`udp: 'tcp'`）：某些服务器只支持 TCP 时勾选。
- **全局 / 按应用**：全局模式下所有流量进隧道；按应用模式只放行已勾选的应用，并排除自身（避免回环）。
- **远程 DNS**（`mapdns`）：开启后把 DNS 请求映射到 `198.18.0.2` 走隧道，避免 DNS 泄漏/被拦截。

## 5. 日志系统

- 开关：`Preferences.LogEnabled`（默认开），在 `LogActivity` 页面用「记录日志」开关控制，**下次连接生效**。
- 落盘位置：`/data/data/dev.sockstun/cache/tproxy.log`（应用私有目录，无需额外权限）。
- 读取：`LogActivity` 每 1.5s 自动刷新并滚到底部；可手动「刷新」「清除」（清除建议在断开后做，否则原生仍持有 fd）。
- 为什么用 fd 重定向而不是直接读 logcat：Android 上 App 原生 `printf/fprintf` 默认被丢弃，而该预编译库的 `log-file` 配置项在本项目中未生效；`Os.dup2` 把进程 1/2 号 fd 指向日志文件，能稳定抓到原生 `[D]/[W]/[E]` 日志。
- 排查“没流量”时，先看日志里有没有连接服务器、握手、DNS 解析、转发的报错行，通常能直接定位是地址/端口、认证还是路由模式的问题。

## 6. 版本号自动递增

- 文件：`app/version.properties`（首次打包自动生成，初始 `VERSION_CODE=12`、`VERSION_NAME=8.0`）。
- 机制：`app/build.gradle` 在**打包任务**（`assemble` / `bundle` / `install` / `build`，含 Android Studio 的 Run 与 Build APK）执行时：
  - `versionName` 增加 `0.01`（用 `BigDecimal` 精确计算，避免浮点漂移，2 位小数）；
  - `versionCode` 增加 `1`（保证新包可覆盖安装/上架）；
  - 写回 `version.properties` 持久化。
- 仅同步 Gradle、执行 `clean`、`tasks` 等查询类任务**不会**递增，避免无谓跳动。
- APK 文件名会变成 `dev.sockstun-<版本>.apk`。

## 8. 一次完整的“连接”时序（文字版）

```
用户点连接
  └─ MainActivity: Enable=true; startService(ACTION_CONNECT)
       └─ TProxyService(:native 进程) onStartCommand → startService()
            ├─ Preferences 读取当前配置档
            ├─ Os.dup2 重定向 stdout/stderr → cache/tproxy.log
            ├─ VpnService.Builder 建立 TUN(tunFd)
            ├─ 写出 cache/tproxy.conf (YAML)
            ├─ TProxyStartService(conf, tunFd)  ← native 开始转发
            └─ startForeground 常驻通知

断开：
  startService(ACTION_DISCONNECT) → stopService()
       ├─ TProxyStopService()
       ├─ 关闭 tunFd、停通知
       └─ System.exit(0) 结束 :native 进程
```
