# tunVPN 启动流程与架构说明

本文档说明项目结构，以及从「点击连接」到「隧道转发」的完整链路，方便排查“连上了但没流量”“节点没切换”之类的问题。

> 包名 `com.tunvpn`，应用名 `tunVPN`（Java 源码包同样是 `com.tunvpn`，即 `app/src/main/java/com/tunvpn/`）。当前引擎是内嵌的 **mihomo（Clash.Meta）**，不是早期的 `libhev-socks5-tunnel`。旧文档里关于 `TProxyStartService` / `tproxy.conf` / `mapdns` / JNI 契约的内容**已全部作废**。
>
> **改包名的影响**：`applicationId` 一变就等于换了一个应用 —— 无法覆盖安装旧版本，
> 旧的 `SharedPreferences`（`/data/data/<pkg>/shared_prefs/SocksPrefs.xml`）也不会迁移，
> 首次启动是全新配置。
>
> ⚠️ **包名必须至少两段**。单段包名（比如 `tunvpn`）会在 `processDebugMainManifest`
> 阶段直接失败：`Package name 'tunvpn' ... should contain at least one '.' (dot) character`。
> 三条一起改才不会踩坑：`build.gradle` 的 `namespace` + `applicationId`、Java 源码目录与
> `package` 声明。另外 AGP 8 起 manifest 里**不要再写 `package=`**（会被忽略并给出
> 警告），包名统一由 `namespace` 提供。
> 名称已全线统一：主题样式名（`Theme.TunVPN*` / `Widget.TunVPN.*` /
> `TextAppearance.TunVPN.*`）、应用图标 `@mipmap/tunvpn`、TUN 设备名、日志首行、
> VPN 会话名（`setSession()`，系统 VPN 列表里显示的就是它）和订阅 `User-Agent`
> 都改成了 `tunVPN` / `tunvpn`。
>
> 唯一保留旧名的是 `SharedPreferences` 文件名 `SocksPrefs`（`Preferences.PREFS_NAME`）：
> 它只是磁盘上的文件名，改了等于清空所有用户配置，不值当。

## 2. 引擎：内嵌 mihomo

- 库：`libmihomo-android` AAR（mihomo v1.19.30），在 `app/build.gradle` 里固定 `v0.3.3`，首次构建从 GitHub Releases 下载并解包到 `app/thirdparty/mihomo/`。
- 只取 AAR 里的 `classes.jar` 和 `jni/<abi>/*.so`；`res/` 与 `AndroidManifest.xml` 故意不合并（会搞崩 AGP 资源合并）。
- **重要坑**：`io.github.oviron.libmihomo.Clash` 是 Kotlin `object`，编译后方法都是**实例方法**，Java 侧必须写 `Clash.INSTANCE.xxx()`，直接 `Clash.xxx()` 会报 “non-static method cannot be referenced from a static context”。

主要调用：

```java
Clash.INSTANCE.load(nativeLibraryDir);              // 加载 libclash.so + libmihomo-jni.so
Clash.INSTANCE.quickSetup(initParams, setupParams, callback);
Clash.INSTANCE.setEventListener(callback);           // 内核日志
Clash.INSTANCE.startTUN(fd, tunInterface, "tunvpn", stack, address, dns, mtu);
Clash.INSTANCE.invokeAction(action, callback);       // 切换策略组里的节点
Clash.INSTANCE.getTraffic();                         // {"up":..,"down":..}
Clash.INSTANCE.stopTun();
```

## 3. 启动流程

三条入口（首页按钮 / 快捷磁贴 / 开机自启）最终都汇聚到 `TProxyService`。

`startService()` 顺序：

1. **读配置** `new Preferences(this)`（当前配置档）。
2. **日志重定向**（可选）：反射调用 `Os.dup2` 把 fd 1/2 指到 `cache/tproxy.log`。
3. **加载内核** `Clash.INSTANCE.load(...)`，失败写日志 + Toast + `stopSelf()`。
4. **生成配置** `MihomoConfig.build()` → `files/mihomo.yaml`（见 §4）。
5. **建立 VPN** `VpnService.Builder`：
   - 地址 `198.18.0.1/24`、`fc00::1/64`，MTU 8500；
   - 路由 `0.0.0.0/0` 与 `::/0`（全部流量进 TUN，由内核规则引擎决定代理/直连）；
   - 按应用放行（`addAllowedApplication`）或排除自身；
   - `establish()` 得到 `tunFd`。
6. **初始化内核** `quickSetup`，homeDir = `files/`，profile = 上一步的 yaml。
7. **订阅内核日志** `setEventListener` → 写进 `tproxy.log`。
8. **启动 TUN**：`startTUN(tunFd.getFd(), protect 回调, ...)`。`TunInterface.protect(fd)` 转发给 `VpnService.protect()`，避免回环。
9. **应用选中节点**：`applySelectedNode()`（见 §5）。
10. **常驻通知**（渠道 `socks5`，`IMPORTANCE_LOW`）+ **统计采样** `startStats()`（每秒）。

`stopService()`：`stopStats()` → 置 `Enable=false` → 停前台 → `Clash.INSTANCE.stopTun()` → 关 `tunFd` → `stopSelf()`。

## 4. 配置生成（MihomoConfig）

上游来源只看一件事：**是否启用了某台 SOCKS5 服务器**（`SOCKS_ACTIVE` 指向列表中的某一项）。

- 启用了某台服务器 → 用它作为上游，**忽略订阅**；
- 没有启用任何服务器 → 用订阅；
- 两者都没有 → 启动失败并提示。

反向也成立：在订阅里点「使用」选用节点时，会自动清除 SOCKS5 的启用状态（`setActiveSocksId("")`），把上游交还给订阅。两边互斥，不会同时生效。

- **走订阅**：解析各订阅的 `proxies`，**忽略订阅自带的 `proxy-groups` 与 `rules`**，由 App 把节点合并去重后自建 `proxy-groups:` 与 `rules:`（路由规则完全由 App「规则」页接管），再补上缺失的 `dns:` / `log:` / `tun:` 段。
- **走 SOCKS5**：按启用那台服务器生成最小配置（路由规则同样来自 App「规则」页）

```yaml
proxies:
  - {name: "socks5", type: socks5, server: <addr>, port: <port>, udp: true, username: …, password: …}
proxy-groups:
  - {name: "tunvpn", type: select, proxies: ["socks5"]}
rules:
  # 由 App「规则」页生成：用户规则 + 兜底 MATCH → tunvpn
  - MATCH,tunvpn
```

> 改上游模式 / 改 SOCKS5 地址都需要**重启隧道**才生效（配置在启动时生成）。

## 5. 订阅与节点

### 5.1 解析（ClashParser）

`parseAll()` 收集 `proxies:` 下**所有协议**的节点（vmess / vless / trojan / ss / socks5 / hysteria2 / tuic …），不限于 socks5。

解析器要同时兼容两种 YAML 写法：

```yaml
# 块式
proxies:
  - name: node1
    type: vmess
    server: a.b.c
    port: 443

# 单行内联（flow mapping）—— 很多订阅商在用
proxies:
  - {name: node1, server: a.b.c, port: 443, type: vmess, uuid: …}
```

因此：行内 `- {…}` 会交给 `parseFlowMap()` + `splitTopLevel()`（按顶层逗号切分，引号内的逗号不切）；列表项缩进不再假设必须是 2 空格。

### 5.2 节点选择

订阅里策略组的名字各不相同（如 `🔰 选择节点`、`GLOBAL`），所以不能再写死 `GLOBAL`。`ClashParser.parseSelectorGroup()` 从 `proxy-groups:` 里挑：优先名为 `GLOBAL` 的，否则第一个 `select` / `url-test` / `fallback` / `load-balance`，再否则第一个组。

- **启动时**：`applySelectedNode()` 用真实组名发 `{"type":"selector","action":"set","name":<组>,"value":<节点>}`。
- **运行中**：订阅页点「使用」会发 `ACTION_SELECT`，`TProxyService` 直接在已运行的内核上切换，**无需重启**。
- 订阅没有可切换策略组时，会记录日志并提示，不再静默失败。

### 5.3 测速

`SubscribeActivity` 对每个节点 `Socket.connect(server, port, 3000)` 计时：

- `>=0`：可用，绿色显示毫秒
- `-2`：不可用，红色
- `-1`：未测速，灰色

结果随节点缓存一起持久化（`ClashNode.encode()` 里的 `lat` 字段），退出页面不丢。列表支持按「订阅顺序 / 延迟」排序，以及「全部 / 仅可用 / 仅不可用」筛选。

> 这是到节点服务器的 **TCP 握手延迟**，只代表链路快慢，不代表实际带宽。

## 6. 统计与通知

| 数据 | 来源 |
| --- | --- |
| 实时速率 / 本次 / 累计 | `Clash.INSTANCE.getTraffic()`（`up` / `down`） |
| 每应用用量 | 系统 `TrafficStats.getUidTxBytes/getUidRxBytes`（连接时打基线，断开时结算） |

每应用数据**包含该应用未走隧道的流量**（Android 无按应用统计隧道流量的 API），仅供参考。

通知：标题 = 当前节点（过长由系统省略），正文 = **实时速率**（保证不被挤掉），展开后是 节点 + 实时 + 本次 + 累计，并有「断开」按钮。

## 7. 多配置档与持久化

- `SharedPreferences` 文件 `SocksPrefs`，按配置档隔离，key 前缀 `P<index>.`。
- `Selected` 当前档位，`ProfileCount` 数量（上限 13）。新增 = 复制当前档；删除 = 后续下标平移。
- 首次启动把旧的扁平 key 迁进第 0 档（`Preferences.migrate()`）。

主要 key：

| Key | 含义 |
| --- | --- |
| `P<n>.Subscriptions` / `SubActive` | 多个订阅地址（JSON）、当前默认订阅 id |
| `P<n>.SubUrl` / `SubRaw` / `SubNodes` / `SubSelected` | 当前订阅的地址、订阅原文、节点缓存（JSON）、选中节点名 |
| `P<n>.Upstream` | 上游模式（0/1/2） |
| `P<n>.SocksAddr` / `SocksPort` / `SocksUser` / `SocksPass` | 手动 SOCKS5 上游 |
| `StatsTotalTx/Rx`、`StatsSessionTx/Rx`、`StatsRateTx/Rx` | 流量 |
| `StatsAppBase` / `StatsAppTotal` | 每应用基线 / 累计 |

## 8. 日志

- 开关 `LogEnabled`（默认开），**下次连接生效**。
- 落盘 `cache/tproxy.log`（应用私有目录）。内核日志通过 `setEventListener` 一并写入。
- 启动阶段的致命错误用 `appendLog()` 直写文件，不受开关影响。

## 11. 一次「连接」的时序

```
点连接
 └─ MainActivity: Enable=true; startService(ACTION_CONNECT)
      └─ TProxyService(:native) → startService()
           ├─ Preferences 读当前档
           ├─ Os.dup2 重定向 stdout/stderr → cache/tproxy.log
           ├─ Clash.INSTANCE.load(nativeLibraryDir)
           ├─ MihomoConfig.build() → files/mihomo.yaml   ← 订阅 或 手动 socks5
           ├─ VpnService.Builder → establish() → tunFd
           ├─ Clash.INSTANCE.quickSetup(homeDir, profile)
           ├─ Clash.INSTANCE.setEventListener(...)
           ├─ Clash.INSTANCE.startTUN(fd, protect 回调, …)
           ├─ applySelectedNode()  ← 在真实策略组里选中节点
           ├─ startForeground() 常驻通知（标题=节点，正文=速率）
           └─ startStats() 每秒采样 getTraffic() / TrafficStats

运行中换节点：
 订阅页点「使用」→ startService(ACTION_SELECT)
      └─ TProxyService 直接在已运行内核上 invokeAction 切换（不重启）
```
