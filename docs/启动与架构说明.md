# SocksTun 启动流程与架构说明

本文档说明本项目的整体结构，以及应用从「点击启动」到「原生隧道运行」的完整链路，方便排查“连上了但没流量”之类的问题。

> 包名：`hev.sockstun`。历史版本曾用过 `dev.socks2tun`，旧文档里残留的路径以本文为准。

---

## 1. 应用入口与组件

| 组件 | 作用 | 所在进程 |
| --- | --- | --- |
| `MainActivity` | 首页：连接/断开按钮、配置档切换、流量卡片、左侧抽屉菜单 | 主进程 |
| `TProxyService` (`VpnService`) | 建立 VPN 接口、生成配置、拉起原生隧道、统计采样 | **`:native` 独立进程** |
| `QSTileService` (`TileService`) | 系统快捷开关（下拉栏里的一键连接） | 主进程 |
| `ServiceReceiver` (`BroadcastReceiver`) | 监听 `BOOT_COMPLETED` 实现开机自启 | 主进程 |
| `ServerActivity` / `DnsActivity` | 服务器、DNS 设置页 | 主进程 |
| `MainActivity` 流量卡片 | 流量统计（实时/本次/累计 + Top 应用） | 主进程 |
| `RoutingActivity` | 分流设置页（全局 / 按应用） | 主进程 |
| `RulesActivity` | 路由规则页（域名 / IP / IP 段 → 代理或直连） | 主进程 |
| `AppListActivity` | 按应用模式的应用勾选页 | 主进程 |
| `LogActivity` | 查看/开关运行日志 | 主进程 |
| 原生库 `libhev-socks5-tunnel.so` | 真正做 SOCKS5 / TProxy 转发的引擎 | `:native` 进程 |

> 注意：`TProxyService` 在清单中被声明为 `android:process=":native"`，因此原生隧道、日志重定向、统计采样都发生在**另一个进程**里。跨进程共享状态用的是 `Context.MODE_MULTI_PROCESS` 的 `SharedPreferences`（文件名 `SocksPrefs`），写入一律用 `commit()`（不是 `apply()`），读取方每次 `new Preferences(context)` 触发一次重载。

## 2. 三条启动路径

### 2.1 桌面图标启动（最常用）
1. 点击启动图标 → `MainActivity.onCreate`。
2. 申请通知权限（Android 13+，`POST_NOTIFICATIONS`），否则后面的常驻通知不会显示。
3. 请求 VPN 权限：`VpnService.prepare(this)`，未授权则弹出系统授权框。
4. 用户点「连接」(`button_control`)：
   - 先把 `Enable` 置为 `true`；
   - `startService(new Intent(this, TProxyService.class).setAction(ACTION_CONNECT))`；
   - 通知快捷开关刷新（`QSTileService.requestUpdate`）。

### 2.2 系统快捷开关（Quick Settings Tile）
- `QSTileService.onClick`：
  - 已连接 → 置 `Enable=false` 并 `startService(ACTION_DISCONNECT)`；
  - 未连接 → 若未授权 VPN 则先拉起 `MainActivity` 去要权限，否则直接 `startForegroundService(ACTION_CONNECT)`。

### 2.3 开机自启
- `ServiceReceiver` 收到 `BOOT_COMPLETED`：若 `prefs.getEnable()` 为真，直接 `startForegroundService(TProxyService, ACTION_CONNECT)`。

> 三条路径最终都汇聚到 `TProxyService`，所以“启动逻辑”只写在一处。

## 3. TProxyService 内部流程（核心）

`onStartCommand`：收到 `ACTION_DISCONNECT` 就停，否则进入 `startService()`。

`startService()` 按顺序做：

1. **读取配置**：`new Preferences(this)`，拿到当前选中配置档的所有参数。
2. **日志重定向**：若 `LogEnabled` 为真，用 `android.system.Os.dup2`（反射调用）把 fd 1/2 重定向到 `cache/tproxy.log`。
3. **加载原生库**：`System.loadLibrary("hev-socks5-tunnel")`，失败则写日志 + Toast + `stopSelf()`。
4. **建立 VPN 接口** `VpnService.Builder`：
   - 地址：IPv4 `198.18.0.1/32`、IPv6 `fc00::1/128`，MTU `8500`；
   - DNS：本地 DNS 或「远程 DNS」时填 `198.18.0.2`（配合原生 `mapdns`）；
   - 路由：**由路由规则决定**（见 §5），无规则时下发 `0.0.0.0/0` 与 `::/0`；
   - 全局模式或按应用放行（`addAllowedApplication` / `addDisallowedApplication` 排除自身）；
   - `builder.establish()` 拿到 `tunFd`。
5. **生成原生配置** `cache/tproxy.conf`（YAML，见 §4.2）。
6. **拉起原生隧道** `TProxyStartService(conf, tunFd)`。
7. **常驻通知**：`startForeground(1, …)`，渠道 `socks5`（`IMPORTANCE_LOW`）。
8. **启动统计采样**：`startStats(prefs)`，每秒一次。

`stopService()`：
1. `stopStats()`（最后一次采样 + 落盘 + 结算每应用用量）；
2. 置 `Enable=false`、停前台；
3. `TProxyStopService()`；
4. 关闭 `tunFd`；
5. `System.exit(0)` 结束 `:native` 进程（下次连接重新拉起）。

### 3.1 每秒采样做三件事

| 任务 | 数据来源 | 落盘 |
| --- | --- | --- |
| 速率与总量 | `TProxyGetStats()`（原生字节计数器） | `setStats()`：总累计/本次/速率 |
| 每应用用量 | `TrafficStats.getUidTxBytes/RxBytes` | 连接时打基线，断开时结算进 `StatsAppTotal` |

采样结果与 UI 进程之间没有 IPC，全部走 `SocksPrefs`。

## 4. 配置体系

### 4.1 多配置档
- 所有设置保存在 `SharedPreferences`（`SocksPrefs`），按**配置档**隔离：每个档位用 `P<index>.xxx` 作为 key 前缀。
- `Selected` 决定当前档位，`ProfileCount` 记录数量（上限 `MAX_PROFILES = 13`）。
- 新增档位 = 复制当前档位；删除档位会平移后续下标。
- 各设置页在 `onPause` 时写回当前档位。
- 首次启动会把旧的扁平 key 迁移进第 0 个档位（`Preferences.migrate()`）。

### 4.2 原生库看到的 YAML（`cache/tproxy.conf`）

```yaml
misc:
  task-stack-size: 81920
tunnel:
  mtu: 8500
  icmp: 'reply'
socks5:
  port: 1080
  address: '1.2.3.4'
  udp: 'udp'            # 或 'tcp'（UDP over TCP）
  udp-address: '…'      # 可选
  username: '…'         # 两者都填才生成
  password: '…'
mapdns:                 # 仅当“远程 DNS”开启
  address: 198.18.0.2
  port: 53
  network: 240.0.0.0
  netmask: 240.0.0.0
  cache-size: 10000
```

> 原生引擎只认 `misc / tunnel / socks5 / mapdns` 这四段，**没有规则引擎、没有包计数器、没有连接表导出**。所有域名/IP 级能力都在 Java 层借助 VPN 路由表实现（见 §5）。

### 4.3 统计与规则相关的 key

| Key | 含义 |
| --- | --- |
| `StatsTotalTx` / `StatsTotalRx` | 跨会话累计流量（字节，来自原生库） |
| `StatsSessionTx` / `StatsSessionRx` | 本次连接的流量 |
| `StatsRateTx` / `StatsRateRx` | 实时速率（字节/秒） |
| `StatsAppBase` | 连接时的每应用计数器基线 `pkg:tx:rx;…` |
| `StatsAppTotal` | 每应用累计流量 `pkg:tx:rx;…` |
| `SubUrl` / `SubNodes` / `SubSelected` | 订阅地址、解析出的节点（JSON）、当前选中节点名 |
| `P<n>.Rules` | 路由规则 `type|value|action;…`（0 域名 / 1 IP / 2 CIDR，action 1 代理 0 直连） |
| `P<n>.RulesDefaultProxy` | 未命中规则时是否走代理（默认 true） |

## 5. 路由规则：能做什么、不能做什么

原生引擎是纯 tun2socks，它把 TUN 里收到的东西**全部**转发给 SOCKS5。所以“代理 / 直连”只能靠 Android 的 VPN 路由表来切：

| 模式 | 做法 | 系统要求 |
| --- | --- | --- |
| **默认走代理**（`RulesDefaultProxy=true`，黑名单独） | `addRoute("0.0.0.0",0)` + `excludeRoute(IpPrefix)` 把「直连」条目排除 | `excludeRoute` 是 **API 33（Android 13）**；低版本自动退化为白名单语义并在日志写 `WARN: direct rules need Android 13+, they were ignored` |
| **默认走直连**（白名单） | 只 `addRoute()` 「代理」条目的网段，其余根本不进 VPN | 全版本（minSdk 24） |

域名规则：连接时用系统 DNS 解析（后台线程，最多等 10 秒），把结果按 `/32`、`/128` 下发。因此**只覆盖连接那一刻解析到的 IP**，CDN / 多 IP 场景可能漏，重连会重新解析。

每次连接都会写一行日志，便于核对：
```
routes: 3 proxy, 2 direct, added 3, excluded false
```

## 6. JNI 契约（改动 native 声明前必读）

预编译的 `libhev-socks5-tunnel.so` 通过 `JNI_OnLoad` + `RegisterNatives` 动态注册，表里有且仅有：

```
类:  hev/sockstun/TProxyService
TProxyStartService  (Ljava/lang/String;I)V   →  必须声明为 void
TProxyStopService   ()V                      →  必须声明为 void
TProxyGetStats      ()[J                     →  long[]
```

`RegisterNatives` 用「方法名 + 完整签名（**含返回类型**）」查找 Java 方法。若把 `void` 写成 `boolean`（即 `(… )Z`），注册会静默失败：`System.loadLibrary` 依然成功，但调用时抛

```
java.lang.UnsatisfiedLinkError: No implementation found for
boolean hev.sockstun.TProxyService.TProxyStartService(java.lang.String, int)
```

`TProxyGetStats()` 返回 `long[]{ tx字节, rx字节 }`；若发现上下行反了，改 `TProxyService` 里的 `STATS_TX` / `STATS_RX` 两个常量即可。

## 7. 流量统计的口径

| 口径 | 来源 | 准确度 |
| --- | --- | --- |
| 隧道总量（实时/本次/累计） | 原生库 `TProxyGetStats()` | 准确，就是进出 TUN 的字节 |
| 每应用用量 | 系统 `TrafficStats.getUidTxBytes/getUidRxBytes` | 近似：包含该应用未走隧道的流量（Android 没有“按应用统计隧道流量”的 API） |

- 每应用「累计」在**断开时结算**；`:native` 进程被强杀时最后一次会话会丢失（隧道总量每秒落盘，不受影响）。
- 页面每 1.5 秒刷新一次。

---

## 8. 日志系统

- 开关：`LogEnabled`（默认开），在「日志」页切换，**下次连接生效**。
- 落盘：`/data/data/hev.sockstun/cache/tproxy.log`（应用私有目录）。
- 为什么用 fd 重定向而不是 logcat：Android 上 App 原生 `printf/fprintf` 默认被丢弃，把 fd 1/2 指向日志文件才能抓到原生 `[D]/[W]/[E]` 日志。
- 启动阶段的致命错误（`appendLog`）**不受日志开关影响**，一定会写入，方便定位加载失败。

## 9. 版本号自动递增

- 文件：`app/version.properties`（首次打包自动生成，初始 `VERSION_CODE=12`、`VERSION_NAME=8.0`）。
- `app/build.gradle` 在**打包任务**（`assemble` / `bundle` / `install` / `build`）执行时：`versionName +0.01`、`versionCode +1`，并写回文件。
- 仅同步 Gradle、`clean`、`tasks` 等查询类任务不会递增。

## 11. 一次完整「连接」的时序

```
用户点连接
  └─ MainActivity: Enable=true; startService(ACTION_CONNECT)
       └─ TProxyService(:native) onStartCommand → startService()
            ├─ Preferences 读取当前配置档
            ├─ Os.dup2 重定向 stdout/stderr → cache/tproxy.log
            ├─ System.loadLibrary("hev-socks5-tunnel")
            ├─ VpnService.Builder
            │     ├─ addAddress(198.18.0.1/32 | fc00::1/128)
            │     ├─ applyRoutes()   ← 按规则 addRoute / excludeRoute
            │     └─ establish() → tunFd
            ├─ 写出 cache/tproxy.conf (YAML)
            ├─ TProxyStartService(conf, tunFd)  ← 原生开始转发
            ├─ startForeground(1) 常驻通知（含流量）
            └─ startStats() 每秒采样：字节 / 每应用

断开：
  startService(ACTION_DISCONNECT) → stopService()
       ├─ stopStats()：最后采样 + 落盘 + 结算每应用用量
       ├─ TProxyStopService()
       ├─ 关闭 tunFd、停通知
       └─ System.exit(0) 结束 :native 进程
```
