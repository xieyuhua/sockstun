# mihomo 内核接口参考（external-controller）

内嵌内核是 **mihomo（Clash.Meta）v1.19.30**（由 `libmihomo-android v0.3.3` 提供），自带一套 RESTful 控制接口（俗称 external-controller / Clash API）。路由、协议握手、连接表、流量统计内核都算好了，直接问内核比自己实现更准。

本文说明：**怎么访问**、接口总览、各接口字段与对 App 的价值、以及坑位。

> 参考：[mihomo APIs 官方文档](https://wiki.metacubex.one/api/)（按 v1.19 时代的分组整理）。

---

## 1. 两种访问方式

### 1.1 进程内动作桥（App 首选）

这个 libmihomo 构建**经常不真正监听 9090 的 HTTP 端口**（表现为「9090 never listens」），所以 App 内部主要通过 **JNI 动作桥**访问内核，完全不需要 HTTP listener：

```java
// TProxyService.apiAction(method, data)
Clash.INSTANCE.invokeAction("{\"id\":\"\",\"method\":\"getConnections\",\"data\":null}", callback);
// 返回 {"id":"","method":"getConnections","data":{...},"code":0}
```

- `code == 0` 时 `data` 就是对应 REST 端点的响应体（同形）。
- 支持的 method 见 [开发与架构 §2.2](开发与架构.md)。
- **桥只支持单次在途回调**，`apiAction()` 已用锁串行化所有调用；新增调用请一律走 `apiAction()`。

### 1.2 HTTP external-controller（REST）

App 生成的配置里写入 `external-controller: 127.0.0.1:<API_PORT>` 并设置 `secret`。`API_PORT` 由 `MihomoConfig.pickApiPort()` 在 `9090..9100` 中取第一个空闲口（默认 9090）。

| 项目 | 值 |
| --- | --- |
| 地址 | `127.0.0.1:<API_PORT>`（自动生成配置与自定义配置都会被 App 对齐到回环） |
| 认证 | **有** `secret`。每个请求需带 `Authorization: Bearer <secret>`，否则 401 |
| 前缀 | 无，直接 `http://127.0.0.1:<port>/xxx` |

> `secret` 值在 设置 → 控制接口密钥 可查看 / 重置。App 侧是 `Preferences.getSecret()`（key `ApiSecret`）。
>
> 自定义配置模式（`CustomConfig`）下，App 会在启动时做一次「必需项对齐」：`external-controller` 改写为 `127.0.0.1:<API_PORT>`、补齐 `secret` 与 `mixed-port`。之所以强制回环：本构建里 mihomo **绑定 `0.0.0.0` 会静默失败**（“9090 never listens”，浏览器也连不上），而 `127.0.0.1` 能正常监听。

### 1.3 在 PC 上调试

```bash
adb forward tcp:9090 tcp:9090
curl -s http://127.0.0.1:9090/version
curl -s -H "Authorization: Bearer <secret>" http://127.0.0.1:9090/connections
```

隧道跑起来的前提下，这样能直接看真实返回，比在 App 里加日志快得多。

### 1.4 流式推送

`/traffic`、`/logs`、`/memory`、`/connections` 支持实时推送，两种连法：

1. **WebSocket**：带 `Upgrade: websocket` 头（面板 yacd / metacubexd 走这条）。
2. **分块流**：不带 `Upgrade` 头直接 GET，内核保持连接、把 JSON 对象一个接一个连续写出（对象间无分隔符）。

第 2 种对 Android 很实用：`HttpURLConnection.getInputStream()` 一直读即可，**无需实现 WebSocket 协议**（代价是要自己按花括号配对切分粘连的 JSON）。

- 下面 JSON 均为**字段示例**，以实际返回为准。

## 3. 数据详解

### 3.1 流量 `/traffic`

```json
{"up": 12340, "down": 567890, "upTotal": 1048576, "downTotal": 20971520}
```

| 字段 | 含义 | 单位 |
| --- | --- | --- |
| `up` / `down` | **当前速率**（不是累计） | 字节/秒 |
| `upTotal` / `downTotal` | 本次内核启动以来的累计 | 字节 |

> ⚠️ `up`/`down` 是**速率**，累计值叫 `upTotal`/`downTotal`。别把速率写进累计字段。

对 App：实时速率可直接读；`*Total` 是内核视角的全部流量（含直连）。App 目前的 实时/本次/累计 取自 JNI 的 `getTotalTraffic()`，与这里同源。

### 3.2 连接表 `/connections`

```json
{
  "downloadTotal": 20971520,
  "uploadTotal": 1048576,
  "memory": 12345678,
  "connections": [
    {
      "id": "8f3c1a2e-...",
      "metadata": {
        "network": "tcp",
        "type": "HTTP",
        "sourceIP": "172.19.0.2",
        "destinationIP": "142.250.66.100",
        "sourcePort": "41234",
        "destinationPort": "443",
        "host": "www.google.com",
        "dnsMode": "fake-ip",
        "uid": 10123,
        "process": "com.android.chrome",
        "processPath": "/data/app/~~xxx/base.apk",
        "specialProxy": "",
        "specialRules": "",
        "remoteDestination": "",
        "sniffHost": ""
      },
      "upload": 1234,
      "download": 56789,
      "start": "2026-09-11T10:00:00.123456789+08:00",
      "chains": ["香港 01"],
      "providerChains": ["机场A"],
      "rule": "DomainSuffix",
      "rulePayload": "google.com"
    }
  ]
}
```

**单条连接字段**

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `id` | 连接唯一 ID | 单独关闭 / 增量统计的 key |
| `metadata.host` | 目标域名（嗅探/fake-ip） | 可读性最好 |
| `metadata.destinationIP` / `destinationPort` | 目标 IP 与端口 | `host` 为空时兜底 |
| `metadata.network` | `tcp` / `udp` | 区分 QUIC 等 |
| `metadata.type` | 入站类型（`HTTP`/`SOCKS`/`TUN`） | 区分混合端口或 TUN |
| `metadata.process` / `uid` | 发起连接的应用包名 / UID | 「哪个 App 在跑流量」 |
| `metadata.dnsMode` | `fake-ip` / `normal` | 排查 DNS |
| `metadata.sniffHost` | 嗅探出的域名 | `host` 不准时补充 |
| `metadata.specialProxy` / `specialRules` | 被强制的代理 / 规则 | 排查「为什么没按规则走」 |
| `upload` / `download` | **该连接**累计收发 | 排序依据 |
| `start` | 连接建立时间（RFC3339，**带时区**） | 看连接活了多久；界面展示连接时间 |
| `chains` | 出口链路（节点名数组） | `["DIRECT"]`=直连；`["香港 01"]`=走节点 |
| `providerChains` | 来自哪个 provider | 多订阅归属 |
| `rule` / `rulePayload` | 命中规则类型与内容 | 验证规则页是否生效 |

**关闭**：`DELETE /connections`（全部）、`DELETE /connections/{id}`（单条）。

对 App：用 `chains != DIRECT` 区分代理 / 直连并累加「代理专属流量」；活跃连接页直接展示；`start` 转本地时间显示连接时间。

### 3.3 节点 `/proxies`

```json
{
  "proxies": {
    "DIRECT": { "name": "DIRECT", "type": "Direct", "alive": true, "history": [] },
    "香港 01": {
      "name": "香港 01", "type": "Shadowsocks", "alive": true,
      "history": [{ "time": "2026-09-11T10:00:00+08:00", "delay": 123 }],
      "provider-name": "机场A"
    },
    "tunvpn": {
      "name": "tunvpn", "type": "URLTest", "alive": true,
      "history": [], "now": "香港 01",
      "all": ["香港 01", "日本 02", "DIRECT"],
      "testUrl": "http://www.gstatic.com/generate_204",
      "interval": 300, "tolerance": 50
    }
  }
}
```

**普通节点**：`name` / `type` / `alive`（最近测速是否成功）/ `history`（`{time, delay}`，`delay` 为 `0` 或缺失代表超时）/ `udp` / `provider-name` 等。

**策略组额外字段**：`now`（当前选中）、`all`（成员）、`testUrl` / `expectedStatus` / `interval` / `tolerance` / `lazy` / `fixed`。

**读单个 / 切换 / 清固定**：

```
GET    /proxies/{name}          → 单个对象
PUT    /proxies/{name}          body {"name":"日本 02"}  → 切换（204）
DELETE /proxies/{name}          → 清除 fixed（204）
```

**读延迟**：

```
GET /proxies/{name}/delay?url=http://www.gstatic.com/generate_204&timeout=5000
→ 成功 {"delay": 123}；失败 HTTP 504 {"message":"An error occurred in the delay test"}
```

对 App：

1. **当前实际出口** = `GET /proxies/tunvpn` 的 `now`（自动模式下只有内核知道）。
2. **真实延迟** = 按需 `/delay`，或 `history`（内核按 `interval` 实测）。App 的节点测速即用 `/delay`。
3. **节点列表** = 合并后的最终名单（含 `alive`）。
4. **切换** = `PUT /proxies/tunvpn`，与 JNI `changeProxy` 等价。

### 3.4 代理集合 `/providers/proxies`

订阅的流量 / 到期时间在这里（`subscription-userinfo` 已被内核解析）：

```json
{
  "providers": {
    "机场A": {
      "name": "机场A", "type": "Proxy", "vehicleType": "HTTP",
      "updatedAt": "2026-09-11T10:00:00+08:00",
      "subscriptionInfo": { "Upload": 123456789, "Download": 987654321,
                            "Total": 107374182400, "Expire": 1798761600 }
    }
  }
}
```

- `updatedAt`：上次更新时间；`subscriptionInfo.Upload/Download/Total/Expire`（Expire 为 Unix 秒）。
- 读单个 / 更新 / 健康检查：`GET|PUT /providers/proxies/{name}`、`GET .../{name}/healthcheck`。

> ⚠️ 前提：订阅服务器在响应头给了 `subscription-userinfo`；字段名首字母大写（Go 序列化结果）。
>
> ⚠️ 本 App 目前**不使用 `proxy-providers`**（是自己拼 `proxies:` 列表），所以内核里**没有 provider 对象**，此接口会是空的。

### 3.5 规则 `/rules`

```json
{
  "rules": [
    { "index": 0, "type": "DomainSuffix", "payload": "github.com", "proxy": "tunvpn",
      "size": -1, "extra": { "disabled": false, "hitCount": 12, "missCount": 3 } },
    { "index": 2, "type": "Match", "payload": "", "proxy": "tunvpn", "size": -1 }
  ]
}
```

- `index` 就是匹配优先级；`proxy` 命中后走谁。
- `extra.hitCount` 能回答「这条规则到底用没用到」；`Match` 那条的 `proxy` = 未命中流量的去向。
- 临时禁用：`PATCH /rules/disable` body `{"0": false, "1": true}`（重启失效）。

### 3.6 配置与版本 `/configs`、`/version`

- `GET /version` → `{"meta": true, "version": "v1.19.30"}`。
- `GET /configs` → 内核**实际生效**的配置（`mode`、`tun`、`mixed-port`、`dns`、`external-controller`、`secret` 等）。`mode` 不是 `rule` 时先看这里（「连上但全直连」的常见原因）。
- `PATCH /configs` 改运行中少量字段（`mode`、`log-level`），**不持久化**；`PUT /configs?force=true` 重载。

### 3.7 日志 / 内存

- `GET /logs?level=info`（流式）→ `{"type":"info","payload":"[TCP] ... using 香港 01"}`，与 App 的 `setEventListener` 同源。
- `GET /memory`（流式）→ `{"inuse": 12345678, "oslimit": 0}`（Go 堆占用）。

### 3.8 缓存与维护

| 接口 | 方法 | 作用 |
| --- | --- | --- |
| `/cache/dns/flush` | POST | 清 DNS 缓存 |
| `/cache/fakeip/flush` | POST | 清 fake-ip 缓存 |
| `/restart` | POST | 重启内核（本 App 的 TUN 是外部传 fd，重启会丢 TUN，慎用） |
| `/dns/query?name=x&type=A` | GET | 用内核解析器查一次域名 |
| `/storage/{key}` | GET/PUT/DELETE | 内核键值存储（≤1MB） |
| `/upgrade*`、`/debug/pprof` | POST/浏览器 | 内嵌场景不适用 / 调试用 |

`/group` 系列是旧接口，等价于 `/proxies` 里 `type` 为 Selector / URLTest / Fallback / LoadBalance 的项。

## 5. 坑与注意事项

1. **动作桥单回调**：所有桥调用必须串行（App 已用 `API_LOCK`），并发会导致结果丢失。
2. **速率 vs 累计**：`/traffic` 的 `up`/`down` 是速率，累计看 `upTotal`/`downTotal` 或 `/connections` 的 `uploadTotal`/`downloadTotal`。
3. **WebSocket 可绕开**：流式端点支持不带 `Upgrade` 头的 GET，直接读流即可。
4. **接口不能用来「改配置」**：配置在启动时一次性生成，`PATCH /configs` 不持久化；改上游 / 节点池 / 规则必须「重新生成配置 → 重启隧道」。
5. **`history` 有限**：只存最近约 10 条，用来算「平均延迟」会失真；`delay: 0` 表示超时。
6. **节点名要 URL 编码**：中文和空格必须编码，否则 404；建议空格编成 `%20`。
7. **secret 必带**：本 App 配置了 `secret`，所有 HTTP 请求都要 `Authorization: Bearer <secret>`（含流式那四个）。
8. **自定义配置的 `external-controller` 会被对齐**：App 启动时把它改写为 `127.0.0.1:<API_PORT>` 并补 `secret`（`0.0.0.0` 在本构建绑定会失败），请勿依赖手写的地址 / 端口。
9. **`start` 带时区**：是节点本地时间（如 `+08:00`），解析时必须保留偏移，不能当 UTC。
